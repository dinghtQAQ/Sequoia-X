# 共享资金的 60 日组合重放

`sequoia_x.research.portfolio.run_portfolio` 是 #12 的公开测量接口。它只产生历史日线模拟账户与数据资格，不产生 B0 或上线通过结论；统计判断由独立检验完成。合成样例永远标为 `synthetic`，不能作为真实收益证据。

## 输入与冻结身份

```python
result = run_portfolio(
    snapshot, frozen_protocol, execution_policy, selection_policy,
    signals=signals,       # None 使用恢复版 MA；空 tuple 是真实空信号账户
    benchmark=levels,      # date -> 正的全收益基准指数水平
    window=window,         # 可省略，默认样本 manifest 的 start..end
)
```

价格为元/股、数量与成交量为股、金额为人民币元，收益和暴露为比例。`PortfolioPolicy` 的 `daily_entry_slots`、`selection`（`symbol_order` 或 `seeded_shuffle`）及 `seed` 必须显式提供。选择政策的 `selection_policy:<policy_id>` 作为独立空白分隔项放入协议 `trading.capacity`，数值执行模型的 `execution_policy:<policy_id>` 作为完整项放入 `trading.fees`，然后再冻结协议。订单时点必须为 `next_session_open_limit`。数值执行模型显式设置 `max_order_quantity`，并把 `limit_at_verified_session_bounds`、卖款拍卖后可用、派息日末可用等语义纳入哈希。修改政策会改变哈希，旧市价协议不能静默复用。应同时保存快照、协议与两项政策的 JSON，单独的哈希不能替代政策原文。

数据快照与股票池必须匹配冻结协议。窗口不可超出样本或协议截止日。`signals` 使用单笔重放模块的 `Signal`，其 `signal_id`、策略名、形态 `episode_id` 贯穿订单、成交与交易，不按盈利结果筛选信号。flag 可以传入自己的信号而完全复用账户。

对照账户也携带自己的冻结策略版本与协议；例如现金对照要在预先登记的 cash-control 协议中运行 `signals=()`，不能事后把同一个 MA 结果改名为现金版本。

## 订单、现金与交易单位

信号在 D 日收盘后形成，基于当时原始收盘价确定请求数量和资金预算，最早在下一个全市场交易日开盘模拟执行；次日停牌不会把订单顺延到有利日期。入场是 next-session 限价 DAY 订单：买限价为事前明确的当日上限，卖限价为下限；开盘价只是日线事后撮合价格。仅支持已核对 `SSE_MAIN`、100 股数量单位、明确双限的普通证券；ST、未知/其他板块、无界限价及不支持的申报量/价格单位均保留拒绝原因，不能把这些证券静默视为可执行。入场请求先按限价及费用缩为有现金支持的实际申报量；未申报部分与交易所部分成交分别记录。已申报但未成交的剩余数量当日过期。所有候选均保留，包含名额不足、资金不足、重复持仓、未知状态、无法成交与期末待执行。

多个证券共享一个现金余额。挂起买单只冻结实际存在的现金，未覆盖部分是待检查的请求，不是借款。在本批拍卖的任何成交前，以原有现金、上一次可知 NAV 和持仓市场总值冻结整批申报。计划退出的证券仍占用名额；不能先看卖清结果再申报买入，也不使用本批开盘价重算预算。买限价及费用占用全部申报资金，同批低于限价成交所释放的价差只能在日末用于下一轮计划，不能给后续同批订单补资金。只有未申报的预算可在事前中性顺序中重分配。拍卖卖款及没有盘中到账时刻的当日派息均不能资助本批买单或卖费，日末才可为下一交易日订单使用。随后按固定顺序模拟卖出与买入撮合，全账户同股成交量共用容量；这一步的结果不改变已冻结的申报与名额。

`max_positions` 约束原有持仓与本批潜在申报的不同证券数，即使其后没有成交也不事后补选。`max_position_fraction` 基于上一次可知 NAV，在拍卖前约束同一证券原有市场总值与新单限价冻结资金的合计分配，不读取本轮实际开盘价格或卖出结果。持仓涨跌可以使后续市值权重越过原始分配比例，重放会如实显示，不凭此添加未经验证的卖出规则。`ignore_while_open` 在有持仓或待入场订单时拒绝同股信号；`independent_signal_lots` 允许独立批次，但仍共享证券仓位与资金限额。每个 signal-lot 的部分买入、部分卖出和公司行动合并成一笔交易，只有股票数量归零后才计入完整交易胜率。

实际首次入场日是第 1 个全市场交易日，停牌照常计时；第 60 个交易日收盘后，在下一全市场交易日开盘尝试卖出。T+1、停牌、跌停及流动性不足不会被期末清仓绕过，未成交退出在后续交易日继续尝试，保留每次原因。日线成交量只是事后模拟上界，不能证明开盘排队或盘中可成交；涨跌停、数量单位和费用规则来自对应历史日的明确状态和政策。

## 公司行动与估值

公司行动在除权日前持有的股份上确认权益，没有盘中到账时间的现金在实际支付日的日末进入可用现金。股票卖清但分红尚未支付时，应收仍进入 NAV。分红实收与扣税分别记录，送转改变数量，成本不重复扣除。缺少必要事件、状态或原始价格时，报告不具备可信收益资格。

每日 NAV 等于现金（包含被冻结部分）加市场持仓价值及分红应收。期末不会虚构卖出。停牌或缺价使用最后可核对市场估值并报告陈旧日期；除权后没有可靠新价时保留明确的不可可靠估值状态，不能用新股数乘除权前价格制造收益。没有可靠估值的日期阻断可信结论，仍保留风险与仓位。

## 输出与复算

`PortfolioResult` 是可 `model_dump(mode="json")` 序列化的冻结模型，保存协议、数据、实现、执行与选择政策身份以及输入信号；`daily_nav` 包含全部交易日和空仓日，记录现金、可用/冻结资金、持仓、应收、费用、净收益和估值标志；`orders`、`fills`、`trades` 和 `corporate_actions` 保存全量账本。请求数量、实际申报数量、未申报数量、限价、申报冻结及日末释放分别保留；逻辑退出订单可多日重试，订单上的申报/释放字段描述最后一次尝试，全量日尝试保存在 `fills`。`execution_qualified` / `execution_reasons` 单列实际执行模型未覆盖的输入，不把数据审计合格当作模型支持全市场；执行不支持也进入总体不可信理由。

交易净盈亏为卖出净回款加分红权益减入场总现金支出；极端最低费用超过卖出成交额时，卖出净现金可以为负，仍须由拍卖前可用现金支付，不能提前花用当日派息或同批其他卖款；未平仓仅报告未实现经济变化。零完整交易时净胜率和每笔净期望是 `None`，缺少盈利组或亏损组时条件均值及盈亏比不可估计。账户累计收益来自 NAV，不是交易收益相加；年化按实际日历跨度计算，回撤包含初始资本峰值。换手、成本、未完成交易和无法退出暴露一并保留。

可选基准输入必须覆盖同一账户日历，按第一日水平归一到相同初始资金；缺少基准明确标为不可估计，不把绝对上涨解释为市场超额。同一冻结协议、政策、快照、窗口和信号可确定性重放。
